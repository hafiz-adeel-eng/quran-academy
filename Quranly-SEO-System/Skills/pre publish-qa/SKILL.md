# QuranlyHub SEO Skill
## Skill #16: Pre-Publish SEO QA
## Version: 1.0

---

# 1. PURPOSE

This skill is the final quality-control gate before publishing any QuranlyHub page.

Its job is NOT to write the article.

Its job is to verify that the completed page is:
- Search-intent aligned
- SEO optimized
- Technically healthy
- Factually accurate
- User-friendly
- Mobile-friendly
- Internally linked
- Properly structured
- Ready for indexing
- Ready for search engines
- Ready for users
- Ready for conversion

The skill must make one final decision:

- PUBLISH
- PUBLISH AFTER FIXES
- BLOCK PUBLISHING

Never recommend publishing a page that has a critical unresolved SEO, technical, factual, UX, or indexing problem.

---

# 2. CORE PRINCIPLE

Publishing is the final step, not the testing step.

Before publishing, verify the page as if a real user, Google crawler, search engine, and business owner will all inspect it.

Do not assume something is correct because another agent created it.

Every important requirement must be verified.

---

# 5. SEARCH INTENT CHECK

Verify:

- Page matches the target keyword intent
- Page type matches SERP expectations
- User's primary question is answered
- Search intent is satisfied early
- Commercial intent is not treated as purely informational
- Local intent is addressed when relevant
- Transactional intent has an appropriate CTA

If intent is wrong:
BLOCK PUBLISHING.

---

# 6. PRIMARY KEYWORD CHECK

Verify:

- Primary keyword is clearly defined
- Keyword is naturally used
- Keyword appears where contextually appropriate
- Keyword is not forced
- Keyword is not repeated unnaturally

Potential locations:
- Title
- H1
- Introduction
- Relevant headings
- Body
- URL where appropriate
- Meta description where natural

Do not force exact-match keywords into every location.

---

# 7. SECONDARY KEYWORDS

Verify that relevant secondary keywords are naturally covered.

Check:
- Related terms
- Synonyms
- Long-tail queries
- Question queries
- Commercial terms
- Location modifiers
- Semantic variations

Do not insert every keyword from a keyword database.

Relevance comes first.

---

# 8. KEYWORD STUFFING CHECK

Flag:

- Repeated exact-match phrases
- Awkward city repetition
- Unnatural keyword variations
- Keyword lists hidden in text
- Repetitive headings
- Keyword-heavy anchors

If wording sounds written for a search engine instead of a human:
FIX IT.

---

# 9. TITLE CHECK

Verify:

- One clear title
- Accurate representation of page
- Matches search intent
- Primary topic is obvious
- Not misleading
- Not clickbait
- Reasonable length
- Differentiated from competing titles

Do not sacrifice clarity merely to fit a character limit.

---

# 10. H1 CHECK

Verify:

- Exactly one primary H1 where site architecture permits
- H1 clearly describes page
- H1 matches content
- H1 is not stuffed with keywords
- H1 is not unnecessarily identical to every other page

---

# 11. HEADING HIERARCHY

Check:

H1
H2
H3
H4

Verify:
- Logical hierarchy
- No random heading jumps
- Headings describe actual sections
- Headings help users scan
- No heading exists solely for keywords

---

# 12. INTRODUCTION CHECK

The introduction should:

- Quickly establish the topic
- Address user intent
- Explain what the page provides
- Avoid unnecessary filler
- Establish relevance
- Naturally introduce the primary topic

Do not waste the first paragraphs on generic statements.

---

# 13. CONTENT COMPLETENESS

Compare the final article against the approved content brief.

Verify:
- Required topics included
- Required subtopics included
- Important questions answered
- Important entities covered
- Search intent satisfied
- Differentiation strategy implemented

If a critical required topic is missing:
PUBLISH AFTER FIXES.

---

# 14. CONTENT QUALITY

Evaluate:

- Accuracy
- Clarity
- Originality
- Usefulness
- Depth
- Practical value
- Readability
- Structure
- Examples
- Trust

Do not judge quality by word count alone.

---

# 15. ORIGINALITY

Verify:

- No copied competitor paragraphs
- No copied competitor headings where distinctive
- No copied examples
- No copied testimonials
- No copied proprietary information
- No copied images
- No copied branding

Competitor research may inform the article but must not become imitation.

---

# 16. FACTUAL ACCURACY

Verify claims involving:

- Prices
- Courses
- Teachers
- Qualifications
- Locations
- Schedules
- Services
- Policies
- Statistics
- Technology
- Religious information

Never invent facts.

If a critical claim cannot be verified:
BLOCK PUBLISHING.

---

# 17. RELIGIOUS CONTENT REVIEW

For QuranlyHub Islamic content:

Check:
- Quran quotations
- Arabic text
- Translations
- Tajweed rules
- Islamic terminology
- Scholarly claims
- Hadith references
- Tafsir claims

Do not invent religious evidence.

If scholarly verification is required:
BLOCK or mark:
"Scholarly review required."

---

# 18. E-E-A-T CHECK

Verify genuine signals of:

Experience:
- Practical teaching information
- Real methodology
- Real process

Expertise:
- Qualified information
- Accurate educational guidance

Authoritativeness:
- Clear organization
- Relevant expertise
- Author information

Trust:
- Contact information
- Transparent business information
- Policies
- Accurate claims

Never fabricate credentials.

---

# 19. AUTHOR CHECK

If an author is displayed:

Verify:
- Real person
- Relevant expertise
- Accurate biography
- Appropriate author page
- No fabricated credentials

If author information is missing where it materially matters:
FLAG FOR REVIEW.

---

# 20. META TITLE CHECK

Verify:

- Unique title
- Accurate
- Search-intent aligned
- Primary topic represented
- No keyword stuffing
- No misleading claims

---

# 21. META DESCRIPTION CHECK

Verify:

- Accurate
- Unique
- Useful
- Relevant
- Natural keyword usage
- Clear value proposition
- Appropriate CTA where useful

Meta description must not promise something the page does not provide.

---

# 22. URL CHECK

Verify:

- Clean URL
- Readable
- Stable
- Relevant
- No unnecessary parameters
- No keyword stuffing

Avoid changing an established ranking URL without a strong reason.

---

# 23. CANONICAL CHECK

Verify:

- Canonical exists where appropriate
- Canonical points to intended URL
- No accidental cross-canonical
- HTTP/HTTPS consistency
- WWW/non-WWW consistency

If canonical is wrong:
BLOCK PUBLISHING.

---

# 24. INDEXABILITY CHECK

Verify:

- Page returns HTTP 200
- Page is indexable
- No accidental noindex
- No accidental nofollow where inappropriate
- Robots.txt does not block required crawling
- Canonical is correct

If page should be indexed but is blocked:
BLOCK PUBLISHING.

---

# 25. ROBOTS CHECK

Check:
- robots.txt
- meta robots
- X-Robots-Tag where applicable

Ensure no accidental:
- noindex
- nofollow
- disallow

Do not modify global robots rules casually.

---

# 26. XML SITEMAP CHECK

Verify:

- URL can be included in sitemap
- Canonical URL is used
- No duplicate URL
- Sitemap structure remains valid

Do not submit non-indexable URLs as primary sitemap URLs.

---

# 27. INTERNAL LINKING CHECK

Verify the page has relevant internal links.

Check links to:
- Homepage
- Relevant services
- Relevant courses
- Related articles
- Location pages
- Contact
- Free Trial
- Relevant supporting content

Do not over-link.

---

# 28. INTERNAL LINK QUALITY

For every important internal link verify:

- Destination exists
- Destination is indexable
- Destination is relevant
- Anchor text is natural
- No broken link
- No unnecessary redirect

---

# 29. ORPHAN PAGE CHECK

Verify the new page can be discovered through the website.

A page should not be published as an isolated orphan unless intentionally designed that way.

Identify:
- Parent page
- Supporting pages
- Related content
- Navigation path

---

# 30. CANNIBALIZATION CHECK

Before publishing ask:

Does another QuranlyHub page target the same search intent?

If yes:
- Differentiate
- Consolidate
- Redirect
- Or do not create the page

Do not publish duplicate intent pages unnecessarily.

---

# 31. ANCHOR TEXT CHECK

Verify internal anchors are:

- Descriptive
- Natural
- Contextual
- Useful

Avoid:
- Repeating exact-match anchor excessively
- Keyword stuffing
- Generic "click here" when a descriptive anchor is possible

---

# 32. EXTERNAL LINKS

If external references are used:

Check:
- Source quality
- Relevance
- Accuracy
- Link validity

Do not link to low-quality sources merely to increase link count.

---

# 33. BROKEN LINKS

Run a final check for:
- Broken internal links
- Broken external links
- Incorrect URLs
- Redirect chains

Any important broken internal link:
FIX BEFORE PUBLISHING.

---

# 34. IMAGE CHECK

For every image verify:

- Relevant
- Original/licensed
- Correct dimensions
- Correct aspect ratio
- Compressed
- Modern format where appropriate
- Proper filename
- Correct alt text
- Lazy loading where appropriate
- No unnecessary oversized files

---

# 35. IMAGE SEO

Verify:

- Filename describes image
- Alt text describes actual image
- No keyword stuffing
- Decorative images use appropriate treatment
- Image dimensions are declared where appropriate
- Important above-the-fold image is not unnecessarily lazy-loaded

---

# 36. IMAGE PERFORMANCE

Check:
- WebP/AVIF where appropriate
- Compression
- Responsive images
- srcset/sizes where applicable
- File size
- LCP image priority

Do not load a 4K image when the displayed image is small.

---

# 37. IMAGE ACCESSIBILITY

Alt text must describe meaningful images accurately.

Example:

Good:
"Student attending an online Quran lesson with a teacher"

Bad:
"Best online Quran classes for kids in Qatar"

- Reviews
- Ratings
- Prices

- Organizations
- Locations

# 67. CRITICAL ISSUES

Any of these can BLOCK publishing:

- Wrong canonical
- Noindex accidentally enabled
- Robots blocking page
- Broken primary CTA
- Broken lead form
- Incorrect critical business information
- Fabricated credentials
- Fabricated testimonials
- Incorrect religious claims
- Broken primary internal links
- Severe mobile layout failure
- Major accessibility failure
- Security issue
- Missing required page content
- Wrong search intent
- Duplicate/cannibalizing page architecture

---

# 68. HIGH PRIORITY ISSUES

Usually fix before publishing:

- Missing meta title
- Missing H1
- Poor internal linking
- Broken secondary links
- Missing alt text
- Poor mobile spacing
- Slow images
- Weak CTA
- Missing relevant schema
- Poor content structure
- Major keyword stuffing

---

# 69. MEDIUM ISSUES

Can be scheduled if they do not affect core quality:

- Minor wording
- Minor formatting
- Optional secondary links
- Small metadata refinements
- Minor image naming issues

---

# 70. LOW ISSUES

Examples:

- Cosmetic improvements
- Minor stylistic changes
- Non-critical spacing differences

Do not delay an otherwise excellent page indefinitely for cosmetic perfection.

# 71. PUBLISH DECISION

Use exactly one:

### PUBLISH
All critical and high-priority checks pass.

### PUBLISH AFTER FIXES
No blocking issue exists, but important improvements should be completed first.

### BLOCK PUBLISHING
A critical issue remains.

# 83. FAILURE CONDITIONS

Return FAIL if:

- Final content is missing
- Target keyword is missing
- Search intent is unknown when required
- URL is missing
- Critical technical information cannot be checked
- Page contains unverifiable critical claims
- Publishing decision would require assumptions
- Data is insufficient to safely approve publication

Never fabricate QA results.

---

# 84. AGENT HANDOFF

If decision is:

PUBLISH:
Pass to Publishing Agent.

PUBLISH AFTER FIXES:
Pass required fixes back to the responsible agent.
Run QA again after fixes.

BLOCK PUBLISHING:
Stop publishing.
Return critical issues to the responsible agent.

After major fixes:
Run this skill again.

---

# 85. POST-PUBLISH HANDOFF

After publishing, monitor:

- Indexing
- Search Console
- Rankings
- Impressions
- CTR
- Conversions
- Crawl errors
- Core Web Vitals
- Broken links
- Rich results

Publishing is not the end of SEO QA.

---

# 86. FINAL PRINCIPLE

Do not ask:

"Does the page look finished?"

Ask:

"Is there evidence that this page is technically sound, useful, accurate, indexable, search-intent aligned, mobile-friendly, and ready for real users?"

If yes:
PUBLISH.

If important fixes remain:
PUBLISH AFTER FIXES.

If a critical problem remains:
BLOCK PUBLISHING.

Never publish simply because the content has been written.

The final standard is:

ACCURATE + USEFUL + ORIGINAL + SEARCH-INTENT ALIGNED + TECHNICALLY HEALTHY + MOBILE-FRIENDLY + TRUSTWORTHY + INDEXABLE + CONVERSION-READY.
